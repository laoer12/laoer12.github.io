zaclab.

生活资料管家

把凭证放回物品，把问题带回原文，把重要日期变成提醒。一个连接 Vue 前端、Java 业务服务与 Python AI 能力的个人全栈项目。

已上线 · 开发中Vue 3 / TypeScriptJava / Spring BootPython / FastAPI

01 / THE PRODUCT

先把资料组织起来，再让 AI 帮忙查。

生活资料经常散落在文件夹、相册和聊天记录里。只有一个文件列表，仍然很难回答“这是谁的保修单”“维修以后保修有没有变”“下次什么时候需要处理”。

zaclab 围绕物品组织资料：建立物品档案，关联凭证和说明，需要时在选定 PDF 范围内提问，通过页码引用核对原文；保修与保养日期由用户确认后进入到期事项。

  • 资料管理：PDF、图片和 Markdown 归档，分类、标签、原件预览与下载。
  • 物品关联：同一物品关联多份资料，解除关联不删除原件。
  • 文档问答：选择本人已解析 PDF，流式展示回答与来源，保留会话。
  • 提醒与消息：管理到期事项、站内消息和用户明确开启的邮件提醒。

02 / SYSTEM DESIGN

前端、业务与模型，各自承担清楚的职责。

Vue / TypeScript资料选择与会话界面
SSE 展示、停止、查看出处
→
Java / Spring Boot身份、文档权限、版本
会话、引用校验、事务保存
→
Python / FastAPI组织模型上下文
DeepSeek 流式调用与异常处理

上传的 PDF 经 PDFBox 按页提取，正文保存到数据库。每次问答，Java 校验所选资料的归属和解析版本，读取获授权的非空页，再将问题、正文与受限历史交给 Python。模型结果经服务端引用校验后保存并返回前端。

部署使用 MySQL、Docker、Nginx 与 HTTPS。模型 Key 留在服务端；浏览器使用 Session 与 CSRF 访问 Java，Java 与 Python 使用独立内部令牌通信。

03 / ENGINEERING DETAILS

在成功路径之外，把状态和失败也交代清楚。

  • 权限与版本：每次生成过程中复查账号、会话和资料有效性；引用包含文档、页码与解析版本。
  • 流式状态：区分生成中、完成、失败与取消，超时或上游截断不冒充正常完成。
  • 解析与原件：后台领取 PDF 解析任务，发布结果时再次确认文档版本和删除状态；原始文件单独保存。
  • 通知边界：邮件服务器受理与实际送达分别理解，不在网络结果不确定时盲目重发。

04 / EVALUATION

先建立基线，再讨论回答有没有变好。

2026 年 10 月 27 日，使用 5 份两页的虚构生活资料，固定 30 道独立单轮问题。覆盖事实提取、跨资料比较、同义改写、无依据、资料冲突与外部诱导文字，走真实上传、PDFBox、Java、Python、DeepSeek 与落库链路。

检查项本轮记录
API 完成 / 落库一致 / 引用映射各 30 / 30；自动协议检查
整段一致性严格审阅28 / 30；助手逐题审阅，未经独立人工复核
首个 delta / 总耗时中位数0.760 秒 / 1.220 秒；独立本机短资料实验
发现的问题一题首尾日期比较矛盾；一题先错误排序再更正

原始回答保留，评分与原始结果分开。引用编号合法并不等于事实正确，这两道不一致回答也没有因为“引用齐全”被算作通过。

这套数据是开发基线：资料短、单轮、诱导样例较简单，不能外推为线上总体准确率，也不能替代独立盲审、长文档或全面安全评测。

05 / CURRENT SCOPE

当前能力与接下来的改进。

当前问答使用所选 1–5 份 READY PDF 的受限全文，正文上限 36,000 字符。独立的关键词搜索尚未接入问答；图片和 Markdown 归档不代表已支持 OCR 或相应内容的问答。模型调用为固定流程，尚未实现多步自主 Agent。

接下来优先处理跨资料日期比较与排序的一致性，用同一固定集记录改动前后差异，再补充独立留出题、长资料干扰和多轮追问。

项目业务代码暂未公开，这个页面用于展示产品、架构和已验证的边界。欢迎通过 邮箱交流具体实现。
